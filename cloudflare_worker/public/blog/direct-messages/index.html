Why it matters

Direct messages gives ForkMesh a concrete mechanism for private node-to-node coordination with encrypt-before-send semantics. Message any node operator directly, with the same encrypt-before-send guarantee as rooms.

Project conversations often carry design, access, and coordination context that infrastructure should not read. In ForkMesh, direct messages addresses that need at the feature level, keeping the behavior close to the repository instead of buried in a detached hosted layer.

How ForkMesh handles it

ForkMesh handles direct messages through the same split it uses across the product: ForkMesh attaches rooms, direct messages, discussions, and browser chat to repository identity while encrypting sensitive payloads before relay.

The behavior is intentionally narrow: Message any node operator directly, with the same encrypt-before-send guarantee as rooms. The mainnode can coordinate reachability and relay traffic without custody of plaintext message bodies.

Title focus: Direct messages stays tied to private node-to-node coordination with encrypt-before-send semantics and the local-first repository model.

Where it fits

Use direct messages when teams need repository-aware conversation without central plaintext custody.

It pairs with the rest of Chat & private sharing because Direct messages keeps private node-to-node coordination with encrypt-before-send semantics connected to the repository, its signatures, and the nodes that serve it.
