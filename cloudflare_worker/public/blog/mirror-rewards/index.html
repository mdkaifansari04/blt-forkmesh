Mirror rewards

Nodes that preserve code get recognized and rewarded for it, with a payouts page tracking what mirroring has earned.

Feature 66 of 72FeatureAccounts, money & rewards3 min read

Why it matters

Mirror rewards gives ForkMesh a concrete mechanism for recognition and payouts for nodes preserving code. Nodes that preserve code get recognized and rewarded for it, with a payouts page tracking what mirroring has earned.

Preservation costs time, disk, bandwidth, and maintenance, so incentives need to point at the nodes and people doing the work. In ForkMesh, mirror rewards addresses that need at the feature level, keeping the behavior close to the repository instead of buried in a detached hosted layer.

How ForkMesh handles it

ForkMesh handles mirror rewards through the same split it uses across the product: ForkMesh links node identity, repository activity, public profiles, and Solana payment flows without changing Git ownership.

The behavior is intentionally narrow: Nodes that preserve code get recognized and rewarded for it, with a payouts page tracking what mirroring has earned. Support can move to maintainers, mirror operators, and contributors while repositories remain local-first.

Title focus: Mirror rewards stays tied to recognition and payouts for nodes preserving code and the local-first repository model.

Where it fits

Use mirror rewards when identity, support, and incentives should follow verifiable node and repository activity.

It pairs with the rest of Accounts, money & rewards because Mirror rewards keeps recognition and payouts for nodes preserving code connected to the repository, its signatures, and the nodes that serve it.
