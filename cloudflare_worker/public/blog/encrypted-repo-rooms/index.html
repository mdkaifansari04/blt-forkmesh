Encrypted repo rooms

Every repository gets chat rooms encrypted end-to-end. The relay sees only ciphertext and persists no message bodies, ever.

Feature 47 of 72E2EChat & private sharing3 min read

Why it matters

Encrypted repo rooms gives ForkMesh a concrete mechanism for repo-scoped rooms encrypted before they touch the relay. Every repository gets chat rooms encrypted end-to-end. The relay sees only ciphertext and persists no message bodies, ever.

Project conversations often carry design, access, and coordination context that infrastructure should not read. In ForkMesh, encrypted repo rooms addresses that need at the feature level, keeping the behavior close to the repository instead of buried in a detached hosted layer.

How ForkMesh handles it

ForkMesh handles encrypted repo rooms through the same split it uses across the product: ForkMesh attaches rooms, direct messages, discussions, and browser chat to repository identity while encrypting sensitive payloads before relay.

The behavior is intentionally narrow: Every repository gets chat rooms encrypted end-to-end. The relay sees only ciphertext and persists no message bodies, ever. The mainnode can coordinate reachability and relay traffic without custody of plaintext message bodies.

Title focus: Encrypted repo rooms stays tied to repo-scoped rooms encrypted before they touch the relay and the local-first repository model.

Where it fits

Use encrypted repo rooms when teams need repository-aware conversation without central plaintext custody.

It pairs with the rest of Chat & private sharing because Encrypted repo rooms keeps repo-scoped rooms encrypted before they touch the relay connected to the repository, its signatures, and the nodes that serve it.
