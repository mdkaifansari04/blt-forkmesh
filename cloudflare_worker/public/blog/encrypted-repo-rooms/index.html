Encrypted repo rooms

Every repository gets chat rooms encrypted end-to-end. The relay sees only ciphertext and persists no message bodies — ever.

Feature 47 of 72E2EChat & private sharing3 min read

Why it matters

Coordination often contains context that should not be readable by infrastructure. This feature gives teams private rooms, direct messages, and repo-linked discussion without central plaintext custody.

Every repository gets chat rooms encrypted end-to-end. The relay sees only ciphertext and persists no message bodies — ever.

How ForkMesh handles it

ForkMesh pairs encrypted rooms and local identity with repository-aware chat surfaces, so conversation can sit beside the code while sensitive material stays protected.

In practice, Encrypted repo rooms is designed as part of the same local-first workflow as the rest of ForkMesh: the desktop node owns the data, the relay coordinates reachability, and the repository remains the durable unit of collaboration.

Where it fits

Use it when project discussion, sharing, and private collaboration should live near the repository but remain under participant control.

Together with the other features in Chat & private sharing, it pushes ForkMesh toward a code forge that can be hosted, mirrored, reviewed, and funded by the people using it.
