Introducing ForkMesh: code that can't be taken down

The ForkMesh team June 23, 2026 6 min read

Every line of code you've ever pushed lives on someone else's server, behind someone else's terms of service, one policy change away from disappearing. ForkMesh exists to end that. It's a distributed Git network where your code stays on your machine, every action is signed with your key, and the people who keep repositories alive actually get paid for it.

Today we're opening up ForkMesh — an open-source desktop node and relay for hosting, mirroring, discovering, and discussing software projects without depending on a single code-hosting company. It is not a GitHub skin and it is not a blockchain repo. It's a different shape entirely: a mesh of peers where the network coordinates, but no one in the middle holds your code hostage.

Why we built it

Centralized forges have been extraordinary for collaboration and catastrophic for resilience. Accounts get suspended. Projects get DMCA'd into the void. Whole communities vanish when a company pivots, gets acquired, or simply decides your repository is no longer welcome. The code didn't break any laws of physics — it was just stored in exactly one place that someone else controlled.

ForkMesh starts from a stubborn premise: the canonical copy of your code is the bare Git mirror on your own disk. The network's job is to help people find it, clone it, talk about it, and mirror it — never to be the single warehouse that can be raided or switched off.

The revolutionary part

Six ideas make ForkMesh feel fundamentally different the moment you use it.

🗄️

Your machine is the server

The relay is a control plane, not storage. Git objects stream from a connected host node — there is no central repo warehouse to seize.

🔑

Keys, not passwords

Your identity is a local Ed25519 keypair. Profiles, issues, and pull requests are cryptographically signed — portable across any relay.

🔒

Chat the relay can't read

Per-repository rooms are encrypted client-side with AES-256-GCM. The relay only ever sees ciphertext envelopes it forwards.

◎

Get paid to mirror

Profiles and repos carry Solana addresses. Host a mirror, earn payouts; merged bounty PRs split the reward to the contributor automatically.

🌐

Federated by design

Anyone can run a relay node, Matrix- and Mastodon-style. No company sits at the center of the network — or owns its leaderboards.

⑂

Signed history in Git

Issues and PRs are append-only signed events that can live as files inside the repository itself — your project's history travels with the code.

01Your machine is the server

When you publish a repository, ForkMesh doesn't upload your packfiles anywhere. Your desktop node opens an outbound encrypted tunnel to the relay, and clone and file-browse requests are routed back through that tunnel to your local mirror on demand. Clone the canonical project exactly the way you'd expect: 

git clone https://forkmesh.com/mainnode/forkmesh

The relay never becomes the source of truth. If it vanished tomorrow, every repository would still exist — fully intact — on the machines that host them. That's the whole point.

02Identity you own

There's no email-and-password gate to start. The desktop node generates a local Ed25519 identity for you, and that key signs your profile, your repository metadata, your issues, and your pull requests. Because identity is a key rather than a row in a company's database, it's yours to carry to any relay in the network.

03Conversations the relay can't read

Every repository gets its own encrypted room. Messages are sealed in your client with AES-256-GCM before they ever touch the wire; the relay's Durable Object forwards opaque ciphertext to connected peers and persists nothing. Coordination, maintainer chatter, release talk — all of it stays between the people holding the room key.

04A network that pays its hosts

Mirroring is the act that keeps open source alive, and ForkMesh treats it as first-class work. Profiles and repositories publish Solana addresses, hosts accrue payouts for the uptime they contribute, and repository bounties settle on a merged pull request — splitting the reward to the contributor who did the work. Keeping code alive stops being a favor and starts being something the network rewards.

05Signed issues and pull requests

Collaboration history shouldn't live in a proprietary silo either. ForkMesh issues and PRs are signed, append-only events that can be represented as files inside the repository: 

forkmesh-pull-event-v1
<author pubkey>
<ts>
sha256hex(title + NUL + base + NUL + head + NUL + patch)

When a maintainer merges, the accepted record becomes part of normal Git history — so the conversation around your code travels with the code, forever.

06No center to capture

Relays are federated. The hosted mainnode offers conveniences — repository catalogs, encrypted rooms, mirror-health indexing, Solana metadata, leaderboards — but it owns none of them by right. Anyone can run their own. The network is a mesh, not a hub, and that's exactly what makes it hard to take down.

ForkMesh is a Git app first. Chat, payments, and discovery exist to support repositories, mirrors, and the maintainers who keep them alive.

This is an MVP — and that's exciting

We'll be honest about where we are: ForkMesh is an early prototype. Live file browsing and clone need at least one host online. git push over the relay isn't production-ready yet, and pull requests today are signed patch records rather than full branch refs. The relay is still a trusted jump layer for connection metadata.

But the foundation that matters is already standing: real Ed25519 identity, real Git mirroring, real encrypted rooms, real Solana payouts, and a real federated relay. Everything from here is building outward from a base that, by design, can't be quietly switched off.
