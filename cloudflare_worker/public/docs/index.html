ForkMesh

Host, mirror, inspect, and collaborate on Git repositories across local desktop nodes, signed inboxes, encrypted rooms, and live clone routes.

ForkMesh is a distributed Git collaboration protocol where code remains on local mirrors while the Worker coordinates discovery, routing, identities, and collaboration records.

You organize work around repositories, host tunnels, Git-over-HTTP clone paths, issues, pull requests, accounts, and encrypted rooms. The Worker is the control plane and relay layer, not canonical Git storage.

Install ForkMesh Desktop Download the desktop app, connect a mirror, then continue to the Quickstart.

The ForkMesh Mental Model

Repositories

Local mirrors remain canonical, with public metadata and live browsing routed through the Worker.

Host tunnels

Desktop nodes attach outbound so browsers and Git clients can reach repos without exposing IP addresses.

Signed inboxes

Issues and pull requests travel as signed events and patch records for maintainers to review.

Encrypted rooms

Room traffic is encrypted before the Worker relays it to connected collaboration clients.

Repository model

Each repository is hosted by one or more desktop nodes that keep a local Git mirror. The public catalog stores metadata such as owner, repo name, description, maintainer key, and last sync time.

  • Canonical code: local Git mirror on the host node.
  • Public discovery: GET /api/repositories
  • Repo route: https://forkmesh.com/<owner>/<repo>
  • Browser view: live tree and blob requests routed to a connected host.

Host tunnel

A desktop node opens an outbound WebSocket tunnel to Cloudflare for each hosted repository. Browsers and Git clients connect to Cloudflare, and the Worker routes requests through the matching Durable Object to the active host.

WS/GET /api/repo/<owner>/<repo>/host Host attach and status
GET /api/repo/<owner>/<repo>/tree?path=... Browse directories
GET /api/repo/<owner>/<repo>/blob?path=... Fetch file content

Git clone

The current production path supports Git upload-pack, which covers clone and fetch style operations. The Worker proxies Git smart HTTP requests to the host tunnel instead of storing packfiles itself. 

git clone https://forkmesh.com/mainnode/forkmesh
GET /<owner>/<repo>/info/refs?service=git-upload-pack Advertise refs
POST /<owner>/<repo>/git-upload-pack Fetch pack data

Issues

Issue events are signed by the author's Ed25519 identity. The Worker can hold pending inbox submissions, but accepted issue history should be represented as repository files. 

forkmesh-issue-event-v1
<type>
<issue number>
<author pubkey>
<ts>
sha256hex(content)

Pull requests

Current PRs are signed patch submissions. A maintainer can review and merge them into the repo, at which point the accepted record becomes part of Git-managed project history. 

forkmesh-pull-event-v1
<author pubkey>
<ts>
sha256hex(title + NUL + base + NUL + head + NUL + patch)

Accounts and identities

Signup is a staged funnel: reserve a public node name, donate with a Solana payment reference to join, then set an email and password for universal login. Treat this as protocol scaffolding, not final product auth.

POST /api/accounts/reserve Claim a node name
POST /api/accounts/finalize Set email and password
GET /api/accounts/<nodeName> Resolve public identity

Encrypted rooms

Room clients use WebSockets. The website also opens a read-only clients observer, so the header can show live network presence without joining chat.

WS /api/repo/<owner>/<repo>/rooms/<room>/ws Join an encrypted room
WS /api/repo/<owner>/<repo>/rooms/<room>/clients Observe room presence

Current limitations

  • Cloudflare is still a trusted jump layer for connection metadata.
  • Fresh file browsing and clone require at least one host online.
  • Git push and receive-pack are not production-ready yet.
  • Pull requests are signed patch records, not full branch or ref PRs.
  • Durable Objects should not be used as heavy long-term Git storage.
