Our story

Code hosting without a single required host.

ForkMesh began with a loss - and a refusal to let it happen again.

The day the code disappeared

One ordinary morning, Md Kaif Ansari opened GitHub to find his repositories gone. No warning he could act on, no second copy to fall back on. Years of work - side projects, experiments, the small tools he'd quietly built for himself and others - vanished behind someone else's policy and someone else's servers.

The code wasn't deleted because it was wrong. It was deleted because it lived in exactly one place, and that place answered to no one but itself.

"If a single account can erase years of work overnight, then we never really owned our code - we were only borrowing it."

So he built the antidote

ForkMesh is what Kaif wished he'd had that morning: a network where your code need not sit on one company's servers, waiting to be locked out. Repositories can be copied to independently operated mirrors, with signed state and integrity checks. External stubs and repositories without a healthy mirror remain clearly labeled; availability improves only when enough authorized, current copies actually exist.

Around that foundation grew everything a modern project needs: issues and milestones, pull requests and releases, encrypted chat, real CI, and AI agents that can pick up an issue and ship a fix - all without surrendering your work to a single point of failure. And because the people who keep the network alive deserve recognition, ForkMesh includes a transparent, non-custodial mainnet-beta community reward program. Test networks require explicit development configuration. Rewards are voluntary incentives, never guaranteed returns; the former custodial bounty flow is frozen for migration.

Where we're headed

Source code is infrastructure. It shouldn't depend on the goodwill of a single host. ForkMesh exists so that the next developer who opens their account to find it empty has somewhere else their work already lives.
