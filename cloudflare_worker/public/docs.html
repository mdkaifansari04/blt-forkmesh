Documentation

ForkMesh documentation

ForkMesh is a distributed Git collaboration protocol where code remains on local mirrors, while the Worker coordinates discovery, live tunnels, encrypted rooms, signed inboxes, and Git-over-HTTP clone routing.

Important boundary: the Worker is not canonical Git storage. It is the control plane and relay layer. Repository objects stream from a connected host node.

Repository model

How ForkMesh stores and exposes code.

Each repository is hosted by one or more desktop nodes that keep a local Git mirror. The public catalog stores metadata such as owner, repo name, description, maintainer key, and last sync time.

  • Canonical code: local Git mirror on the host node.
  • Public discovery: GET /api/repositories.
  • Repo route: https://forkmesh.com/<owner>/<repo>.
  • Browser view: live tree/blob requests routed to a connected host.

Host tunnel

How nodes stay reachable without exposing IP addresses.

A desktop node opens an outbound WebSocket tunnel to Cloudflare for each hosted repository. Browsers and Git clients connect to Cloudflare; the Worker routes requests through the matching Durable Object to the active host.

WS/GET/api/repo/<owner>/<repo>/hostHost attach/status
GET/api/repo/<owner>/<repo>/tree?path=...Browse directories
GET/api/repo/<owner>/<repo>/blob?path=...Fetch file content

Git clone

Native Git-over-HTTP fetch path.

The current production path supports Git upload-pack, which covers clone/fetch style operations. The Worker proxies Git smart-HTTP requests to the host tunnel instead of storing packfiles itself. 

git clone https://forkmesh.com/mainnode/forkmesh
  • GET /<owner>/<repo>/info/refs?service=git-upload-pack
  • POST /<owner>/<repo>/git-upload-pack
  • No production-ready git push/receive-pack route yet.

Issues

Signed collaboration history that can live in Git.

Issue events are signed by the author's Ed25519 identity. The Worker can hold pending inbox submissions, but accepted issue history should be represented as repository files. 

forkmesh-issue-event-v1
<type>
<issue number>
<author pubkey>
<ts>
sha256hex(content)

Pull requests

Patch-based PRs, not GitHub-style branch refs yet.

Current PRs are signed patch submissions. A maintainer can review and merge them into the repo, at which point the accepted record becomes part of Git-managed project history. 

forkmesh-pull-event-v1
<author pubkey>
<ts>
sha256hex(title + NUL + base + NUL + head + NUL + patch)

Accounts and identities

Node names are bound to Ed25519 public keys.

Signup is a staged funnel: reserve a public node name, donate with a Solana payment reference to join, then set an email and password for universal login. Treat this as protocol scaffolding, not final product auth.

POST/api/accounts/reserveClaim a node name (optionally key-signed)
POST/api/accounts/donation-addressGet a Solana join payment request
GET/api/accounts/donation-statusPoll for the Solana payment reference
POST/api/accounts/finalizeSet email + password (active account)
POST/api/accounts/loginLog in by email
GET/api/accounts/<nodeName>Resolve public identity

Encrypted rooms

Presence and chat over Durable Object rooms.

Room clients use WebSockets. The website also opens a read-only clients observer, so the header can show live network presence without joining chat.

  • WS /api/repo/<owner>/<repo>/rooms/<room>/ws
  • WS /api/repo/<owner>/<repo>/rooms/<room>/clients
  • Chat payloads are encrypted in the browser/client before the Worker relays them.

Current limitations

What the MVP does not yet do.

  • Cloudflare is still a trusted jump layer for connection metadata.
  • Fresh file browsing and clone require at least one host online.
  • Git push/receive-pack is not production-ready yet.
  • Pull requests are signed patch records, not full branch/ref PRs.
  • Durable Objects should not be used as heavy long-term Git storage.
