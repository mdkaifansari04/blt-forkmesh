Introducing ForkMesh: code that can't be taken down

The ForkMesh team June 23, 2026 7 min read

Every line of code you have ever pushed lives on someone else's server, behind someone else's terms of service, one policy change away from disappearing. ForkMesh exists to end that with a distributed Git network where your code stays on your machine, every action is signed with your key, and the people who keep repositories alive can get paid for it.

Today we are opening up ForkMesh, an open-source desktop node and relay for hosting, mirroring, discovering, and discussing software projects without depending on a single code-hosting company.

It is not a GitHub skin, and it is not a blockchain repo. It is a different shape entirely: a mesh of peers where the network coordinates, but no one in the middle holds your code hostage.

Why we built it

Centralized forges have been extraordinary for collaboration and catastrophic for resilience. Accounts get suspended, projects get taken down, and whole communities vanish when a company pivots, gets acquired, or decides a repository is no longer welcome.

The code did not break any laws of physics. It was just stored in exactly one place that someone else controlled. ForkMesh starts from a stubborn premise: the canonical copy of your code is the bare Git mirror on your own disk. The network's job is to help people find it, clone it, talk about it, and mirror it.

01 Your machine is the server. The relay is a control plane, not storage. Git objects stream from connected host nodes.
02 Keys, not passwords. Your local Ed25519 identity signs profiles, issues, pull requests, and repository metadata.
03 Chat the relay cannot read. Per-repository rooms are encrypted client-side with AES-256-GCM before relay transit.
04 Get paid to mirror. Profiles and repos can carry payout addresses so hosts and contributors are rewarded.
05 Federated by design. Anyone can run a relay. The network is a mesh, not a company-owned hub.
06 Signed history in Git. Issues and PRs can live as signed, append-only events that travel with the repository.

01. Your machine is the server

When you publish a repository, ForkMesh does not upload your packfiles anywhere. Your desktop node opens an outbound encrypted tunnel to the relay, and clone and file-browse requests are routed back through that tunnel to your local mirror on demand. 

git clone https://forkmesh.com/mainnode/forkmesh

The relay never becomes the source of truth. If it vanished tomorrow, every repository would still exist on the machines that host it.

02. Identity you own

There is no email-and-password gate to start. The desktop node generates a local Ed25519 identity for you, and that key signs your profile, repository metadata, issues, and pull requests. Because identity is a key rather than a row in a company's database, it can move with you to any relay in the network.

03. Conversations the relay cannot read

Every repository gets its own encrypted room. Messages are sealed in your client with AES-256-GCM before they touch the wire, while the relay only forwards opaque ciphertext envelopes to connected peers. Coordination, maintainer chatter, and release planning stay between the people holding the room key.

04. A network that pays its hosts

Mirroring is the act that keeps open source alive, and ForkMesh treats it as first-class work. Profiles and repositories can publish Solana addresses, hosts accrue payouts for the uptime they contribute, and repository bounties can settle on a merged pull request.

05. Signed issues and pull requests

Collaboration history should not live in a proprietary silo either. ForkMesh issues and PRs are signed, append-only events that can be represented as files inside the repository. 

forkmesh-pull-event-v1
<author pubkey>
<ts>
sha256hex(title + NUL + base + NUL + head + NUL + patch)

When a maintainer merges, the accepted record becomes part of normal Git history. The conversation around your code can travel with the code.

06. No center to capture

Relays are federated. The hosted mainnode offers conveniences like repository catalogs, encrypted rooms, mirror-health indexing, Solana metadata, and leaderboards, but it owns none of them by right. Anyone can run their own relay.

ForkMesh is a Git app first. Chat, payments, and discovery exist to support repositories, mirrors, and the maintainers who keep them alive.

This is an MVP, and that is exciting

We will be honest about where we are. ForkMesh is an early prototype. Live file browsing and clone need at least one host online, git push over the relay is not production-ready yet, and pull requests today are signed patch records rather than full branch refs.

But the foundation that matters is already standing: real Ed25519 identity, real Git mirroring, real encrypted rooms, real Solana payout metadata, and a real federated relay. Everything from here builds outward from a base that, by design, cannot be quietly switched off.
